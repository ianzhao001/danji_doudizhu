# AI 设计思路与开源致谢

本文介绍 v1.8 至 v1.9-R4 的 AI 引擎：设计约束、架构、确定性方案、验收方法，以及实际援引的开源项目与研究论文。

> **v1.9 增量**：在 v1.8 内核上将评分核重构为毫手量纲评分，新增明牌世界精确解和过牌推断加权采样，并重构提示候选轮换、过牌反馈和手动改选行为。

> **v1.9-R3 增量**：冻结 v1.9 基线，并以固定叫牌、角色分层和配对 bootstrap 置信区间隔离评估出牌能力；为 PIMC 候选分配公平预算，补齐四带二压力、残局清手优先和序列中继；提示复用一次完整分析，p95 延迟约降低 39%；`legalFollows` 定向生成在 8,134 个等价性样本中保持一致，中位性能约提升 4.75 倍。保留集未检出相对 v1.9 的显著差异，因此不宣称胜率提升；区间包含 0 不构成统计等价证明。

> **v1.9-R4 增量**：引入可注入、可序列化的本地对局记录和困难 AI 决策诊断，为回放坏例分析提供真实数据；修正 PIMC 过牌状态起点、队友救场和绝对控牌保护；同一分析帧跨候选复用明牌求解置换表。受限 SPSA 工具只生成候选，本期未把缺乏统计增益的候选写回正式参数。

## 当前升级候选（尚未发布）

本轮保持纯 TypeScript、离线、公开信息与确定性约束，不引入模型或第三方运行时。先修复模拟和度量中的确定问题：

- rollout 识别完整裸飞机，避免把一手可赢的飞机拆成顺子；农民在队友顶牌时若可合法整手清空，优先结束对局。其余让牌策略保持原行为，不同时增加新的救场启发式。
- 竞技场 self 自证核验每个配对的原始分差，不允许正负错误相消；置信区间按发牌 seed 整组重采样，保留同 seed 三席结果的相关性，缺失或无效区间拒绝通过。
- 分片与合并报告记录实验身份和完整种子计划，拒绝混用不同代码、调参、叫牌条件或缺失分片。旧格式分片必须重新生成，不能补写身份冒充本轮证据。
- 时延语料由冻结 v1.9 策略产生，并记录语料摘要与执行环境，避免候选策略变化同时改变测试输入。

本轮属于模拟正确性与评测可信度升级，不预先宣称胜率提升。历史 Cocos 提示点击记录仍保持原样；推荐变化必须在 Cocos Creator 3.8.8 冷构建后重跑真实点击探针，才能作为新版本发布证据。

## 设计约束与路线选择

两条硬约束决定了整条技术路线：

1. **不依赖外部 API**——游戏是离线单机，任何云端推理都不可接受；
2. **不在本地跑 AI 模型**——不引入神经网络运行时与模型文件。

这排除了当下最强的一批开源方案（DouZero 等深度强化学习系）。本项目的路线是：**吸收"纯规则/搜索"层面的算法思想与评估方法论，全部自研 TypeScript 实现，运行时零新增依赖**。AI 只读取公开状态快照（自己的手牌、各家余牌数、公开底牌、出牌历史），不读取对手隐藏手牌。

## 引擎架构（三档 + 提示）

底座是精确手牌拆解引擎（`ai/decompose.ts`：记忆化 DFS 求最少手数与最优分解，炸弹/火箭默认保护）。v1.8 在其上叠了四个新模块：

| 模块 | 职责 |
| --- | --- |
| `ai/handWeight.ts` | 云城式权重核：组件 power（大牌是资产、小牌是债）+ 出牌评分 = 结构代价主项 + 「剩余手牌权重最大化」项 |
| `ai/rollout.ts` + `ai/pimc.ts` | 确定化蒙特卡洛（PIMC）：对未见牌一致采样 N 副"可能世界"，每个候选着法用廉价走子打完取平均胜负；困难档 48 世界，提示 160 世界 |
| `ai/endgameSolver.ts` | 残局对抗精确解：negamax + 置换表，合并对手模型（全部未见牌并成单一对抗方=能力上界）+ 悲观败线，只输出可靠的必胜 |
| `ai/bidding-eval.ts` | 统一叫牌评分（控牌 + 短手型溢价），三档阈值与玩家叫牌建议同一真相源 |

三档组成（v1.8 全体上移一档，用户裁决）：

- **简单**：组合领出 + 基础配合 + 防送分守卫（不拆炸弹、能清手必清手）≈ 旧普通档；
- **普通**：结构化领出与跟牌（拆解代价白出/白跟，高位不拆结构）+ 喂队友；
- **困难**：普通档全部 + 权重评估 + 记牌 + PIMC 灰区仲裁 + 残局精确解 + 压制期战术；
- **提示**：与困难档同一引擎的高预算档（HINT_PIMC，采样 160 vs 48），首按最优推荐、连按轮换候选。

## 确定性设计（本版的关键工程点）

PIMC 需要随机采样，但本仓库有三条铁律：AI 决策与注入随机源无关、自对弈可复现、不作弊（G14）。方案：**PIMC 内部随机种子 = 快照+历史的规范串 → FNV-1a → mulberry32**，策略签名里的 rng 一个不消费。于是**同一局面永远给出同一决策**，测试可复现、竞技场可逐字节对账；采样数是固定常量（非时间预算），跨机器结果一致。

## 验收方法论（怎么证明"变强"）

- **镜像换位竞技场**（借鉴 DouZero 的评估法）：把升级前的引擎逐字节冻结为基线（`test/fixtures/legacy-ai/`，sha256 防漂移），同一副牌同一席位新旧各打一向，配对分差在对内抵消发牌运气。门槛：困难/普通 ≥+8pp、简单 ≥+10pp。
- **双自证**：self 配对（新 vs 新，镜像差必须精确 0——框架无偏差）与 crippled 配对（故意放弱桩，门必须抓得住——门不是摆设）。
- **消融档**：`--profile=weights-only` 去掉 PIMC 单测权重核贡献，隔离证明 PIMC 净增益。
- v1.8 实测：困难 **+10.17pp**、普通 **+8.33pp**、简单 **+32.17pp**；消融 +6.50pp（PIMC 净增 ≈+3.7pp）；三档分层保持单调（Hard−Normal +8.33pp、Normal−Simple +14.44pp）。

## 开源项目、论文参考与采用边界

以下项目为本版提供了算法思想或方法论参照。**均为思想层面的吸收，未复制任何源代码**；运行时不依赖其中任何一个。

| 项目 | 许可证 | 借鉴内容 |
| --- | --- | --- |
| [kwai/DouZero](https://github.com/kwai/DouZero)（快手，ICML 2021） | Apache-2.0 | ① 镜像换位对战评估法（`evaluate.py` 思路）→ 本项目竞技场强度门的赛制；② 14 牌型完备枚举口径（`move_generator.py`）→ 着法枚举完备性守护门（全子集×识别器对照）。**未使用其强化学习模型** |
| [ZhouWeikuan/DouDiZhu](https://github.com/ZhouWeikuan/DouDiZhu)（云城 AI） | Apache-2.0 | 权重拆牌思想：组件 power/badness 与「剩余手牌权重最大化」的出牌排序 → `ai/handWeight.ts`。改造点：权重不走其 C++ 贪心近似，而是计在本项目精确最少手数分解的组件上 |
| [datamllab/rlcard](https://github.com/datamllab/rlcard)（Rice/TAMU DATA Lab） | MIT | 斗地主规则 Agent 的拆牌骨架与保守跟牌基线作为参照（调研确认其为无配合的朴素规则，未进产品） |
| [DeltaDou](https://www.ijcai.org/proceedings/2019/0176.pdf)（IJCAI'19，Jiang et al.） | 论文 | 对手建模中的「过牌推断」思想 → v1.9 过牌推断加权采样（`collectPassSignals` 识别非配合性过牌、`weighWorld` 对「本可免费同型压制却过牌」的矛盾世界降权、ESS 有效样本护栏防极端历史带偏）。PIMC 主干仍为自研通用实现 |

自研部分（通用算法，不源于任何特定仓库）：PIMC 确定化蒙特卡洛（Perfect Information Monte Carlo）、残局对抗 negamax 与置换表、v1.9 的明牌世界两阵营极大极小求解器（`ai/worldSolver.ts`），以及毫手量纲评分核（`ai/handWeight.ts` 与 `ai/pressure.ts` 的超几何被压概率闭式）。

感谢以上开源项目作者与论文作者的工作。
