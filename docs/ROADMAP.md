# 单机斗地主迭代路线

## 项目定位

本项目是基于 Cocos Creator 3.8.8 的单机斗地主游戏。首版目标是完整单机版：手机竖屏、经典三人斗地主、多难度 AI、本地设置与战绩。

当前 M0、M1、M2、M3、M4、M5 纯逻辑层 + 交互层均已完成并并 main；**M6 发布前打磨、代码、测试、文档与发布打包 gate 均已闭合，首版可发布**。发布收口已闭合：M6-C2/C3a/C3b/C4 编辑器与构建验证、M3 后续 UI 屏、M4-42 困难 AI 纵深、ART-IMPORT-02/03/04/05 美术导入、M6-D4 已知限制登记、M6-D5 冒烟脚本与本次发布烟测均已落证。main 当前口径为 **133 测试文件 / 653 用例全绿、typecheck 净、纯层零 cc**。发布构建已按核心循环改为 `launchScene=lobby.scene`，并完成三档大厅构建态烟测与 390×844 大厅→对局→暂停退出→大厅链路复验。

## 迭代阶段

### M0 项目区初始化

目标：建立可交接的项目文档基线。（已完成）

交付：

- 项目路线图、规则说明、架构说明、任务清单、QA 清单和资源清单。
- 明确后续代码分层、规则范围、移动端体验目标和验收方式。
- 保持现有 Cocos 项目文件不变；用户确认的 M0 美术资源导入作为例外记录在资源清单中。

验收：

- `docs/` 下文档完整。
- 未新增 `.ts`、`.js`、`.scene`、`.prefab`、`.meta` 等实现文件。
- 未执行 Git 初始化。

### M1 核心规则闭环

目标：完成纯逻辑规则层，为后续状态机和 AI 提供稳定能力。

交付：

- 54 张牌模型、洗牌（可注入、可设种子的随机源）、发牌、底牌。
- 牌型识别：单牌、对子、三张、三带一、三带二、顺子、连对、飞机、四带二、炸弹、火箭。
- 合法出牌判断和同牌型大小比较。
- 合法着法与跟牌枚举（`enumerateMoves` / `legalFollows`，供 AI 与 UI 提示复用）。
- 搭建独立于 Cocos 的测试运行器（Vitest），用于规则层单元测试。
- 规则层单元测试。

验收：

- 规则层不依赖 Cocos 节点，可用 Vitest 在编辑器外直接运行测试。
- 常见牌型和非法组合均有测试覆盖。
- 相同种子可复现同一副洗牌结果。

### M2 单局状态机

目标：实现一局斗地主从开始到结算的完整流程，并能在无 UI 下自对弈验证。

交付：

- 三个玩家座位、发牌、经典“叫 + 抢、抢翻倍”流程、底牌归属。
- 回合流转、连续过牌、当前最大出牌、胜负判断。
- 倍数结算：叫抢倍数 × 炸弹/火箭 × 春天/反春天。
- `GameEvent` 事件流（供后续 UI 驱动表现）。
- `flow` 回合驱动器雏形：编排发牌→叫抢→出牌→结算，并为 AI 座位预留思考时延。
- 基线随机合法 AI：仅产出合法着法或过牌，用于无 UI 整局模拟。
- `RoundState` 可序列化（为 M5 断局重开铺垫）。
- 自对弈 harness：连续跑 N 局 AI vs AI。

验收：

- 无 UI 时也能用基线 AI 跑完整局模拟。
- 状态机能拒绝非法动作。
- 自对弈 N 局无非法状态、无死循环、无无限等待。
- 存档序列化往返后状态一致。

### M3 手机竖屏 UI

目标：完成移动端竖屏可玩界面。

交付：

- 主游戏场景、玩家区域、地主标识、底牌展示。
- 手牌选择、出牌、提示（复用 `rules` 的 `legalFollows`）、不要、叫地主/抢地主按钮。
- 通过 `GameEvent` 驱动发牌、出牌、炸弹等动画与音效。
- 结算弹窗、重开入口、设置入口。

说明：本阶段对手暂用 M2 的基线随机 AI，难度 AI 留待 M4。

验收：

- 390x844 竖屏下核心按钮不遮挡手牌。
- 操作反馈清晰，玩家能（对阵基线 AI）完成一整局。

### M4 多难度 AI

目标：在 M2 基线 AI 之上，让两个电脑玩家具备稳定且有差异的出牌体验。

交付：

- 简单：优先合法出牌，策略最小化。
- 普通：基础拆牌、跟牌、保留炸弹。
- 困难：更积极地控制牌权，按局面选择拆牌和炸弹时机。
- 三档难度均复用 `rules` 的着法枚举，仅在选择策略上分级。

验收：

- 各难度 AI 不输出非法动作。
- AI 不破坏状态机，不造成死循环。
- 用自对弈 harness 验证各难度的稳定性与差异化。

### M5 完整单机体验

目标：补齐完整游戏外壳。

交付：

- 本地大厅、难度选择、设置、音效开关。
- 战绩统计、本地存档、断局重开（复用 M2 的 `RoundState` 序列化存档）。
- 基础音效、动画和占位视觉资源替换计划。

验收：

- 从启动到多局游玩流程完整。
- 退出后能保留设置和战绩。
- 断局后重开可从存档恢复继续。
