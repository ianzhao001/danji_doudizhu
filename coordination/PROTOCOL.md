# 多 AI 协作协议（PROTOCOL）

本仓库采用「**规划者 + 执行者 + 审查者**」的跨对话窗口协作（**v1.4 修订·用户指定三 AI 换轨**）。通用仓库规则见 [../AGENTS.md](../AGENTS.md)；本文件只讲**多 AI 任务协作工作流**。窗口之间不共享记忆，**一切状态都在仓库文件里**。

当前三 AI 配置：**规划者 = Claude**（本窗口）、**审查者 = Codex**（兼疑难兜底 + 图像任务执行）、**执行者 = Cursor**。核心协议（角色/铁律/工作流）保持模型无关，能力校准见「角色 × 模型能力校准」。

## 角色（v1.4 三 AI 配置）
- **规划者（Planner·Claude·单一窗口）**：只做方案规划与契约制定——拆任务、定公共 API 契约、按**种子分级**（见铁律 1）预写契约级失败测试、建任务分支；给执行者与审查者分别派发任务书（`tasks/<ID>.md` 与 `tasks/R-*.md`）；维护 BOARD 与文档真相源。**不写产品代码、不逐任务评审、不合并**；每轮由审查者验收回复后做**终局裁定**（BOARD 记裁定；发现问题可责令重开）。**唯一例外：图像/美术类任务（ART-*）的审查由规划者承担**（机械核 + 视觉审）——因该类任务由审查者窗口执行，不可自审自批。
- **执行者（Implementer·Cursor·一或多窗口）**：按任务书在**独立 git worktree** 内只实现声明文件域，使契约级种子转绿、按 spec 用例清单自写覆盖级测试并**跑全量自检**，落盘报告，提交分支后**通知审查者**（不自行合并）。Cocos Creator / IDE / 浏览器调试 / 截图 / 录屏等实操验收与证据采集归执行者；需要用户主观终审的，由执行者准备环境、说明步骤、配合用户完成并记录结论。**快速失败纪律：同一障碍自修不超过 2 轮**——超限、缺能力/环境、或需越域即报告置 `blocked` **转审查者兜底**，不空转、不越域硬解、不削弱测试。
- **审查者（Reviewer·Codex·独立窗口·三顶帽子）**：
  1. **审查**：基于审查任务书 + 自主判断评审实现分支——**逐行细读本任务 diff**（读懂每处改动的正确性，不止核销检查单），核文件域/契约/红线/证据，跑全量 test + typecheck，并对改动的导出符号做**直接消费方定向抽查**；**不做覆盖全仓的回扫**（见铁律 8）。对非文字模态与 GUI 实操（非本人执行的），不亲验、不替用户下主观结论，只审计证据链完整性与可复现说明。
  2. **兜底**：执行者 `blocked` 的任务由审查者**接管修复**——在原分支、原文件域内直接改码；兜底 diff 在报告单列**「兜底修复披露」**段（范围/摘要/自检证据）。兜底仍无解（spec/测试矛盾、契约变更、环境不可达）→ 带全部证据**转规划者裁定**。
  3. **图像执行**：ART-* 文生图/美术生成/导入类任务由审查者以执行者身份完成（生成、导入、取证、视觉自审第一层），报告交**规划者审查**；规划者 `approved` 在案后由审查者本人合并。

  合并权在审查者（铁律 3）：通过 → 报告与 BOARD 写精确机器态 `approved`，本人跑双闸 + `claim/merge/release` 合并入 main，并验收回复规划者。

## 铁律
1. **测试是契约，不可改**。`test/**` 由规划者维护；执行者/审查者（含兜底时）存疑 → 报告提问，**绝不**修改/削弱既有测试。**种子分级（token 经济）**：**契约级**（状态机语义、rules 判定/比较、跨模块 API、防回归钉）由规划者预写失败种子（可经 `coordination/seeds/` 预写、执行者逐字节搬运）；**覆盖级**（视图模型、工具纯岛、UI 派生）可**纯 spec 派发**——spec 列「必须覆盖用例清单」，执行者自写 vitest，审查者核清单逐项落实。执行者自写测试一经提审即视同契约，后续轮次不得回删或弱化。
2. **只动自己任务声明的文件域**；审查者兜底时**继承同一文件域约束**。实现阶段不碰他人模块、不碰 `main`、不碰根 `package.json`/`tsconfig.json`/`cocos.config.json`。
3. **合并权在审查者**：未经报告/BOARD 写明 `approved`，任何人不得合并 `main`；合并只能由审查者用 `./coordination/agentctl.sh claim <ID>` → `merge <ID>` → `release <ID>` 执行（合并前重跑 test/typecheck 全绿）。含兜底修复的任务，合并前报告必须已含「兜底修复披露」；**高风险任务**（见「高风险判定」，含兜底 diff 触及高风险面的情形）置 `approved-pending-planner` 排队，过规划者批量结构性把关后再合并；ART-* 任务须**规划者** `approved` 在案后方可由审查者合并。
4. 共享契约文件（如 `assets/scripts/game/types.ts`、各 `index.ts` 桶）由规划者维护；spec 明示授权的桶内单行导出除外。
5. 纯逻辑层（`rules`/`game`/`ai`/`flow`/`data`）与 ui 纯岛**不得 import `cc`**。
6. **能力边界不转移责任**：实操方（执行者，或 ART 任务中的审查者）完成实操并留可审计证据（截图/录屏/日志/步骤/环境）；用户主观终审只能由用户作最终判断，AI 只备环境、说步骤、记录结论。
7. **阻塞一律先找审查者兜底**：执行者确认搞不定（2 轮自修未过 / 缺能力环境 / 需越域）→ 报告置 `blocked`、列已尝试路径与失败证据 → 交接审查者接管；**不再直通规划者**。审查者兜底后仍属契约/spec/测试/文件域问题 → 打包证据转规划者裁定（改 spec、补/改测试、拆新任务、调整文件域或暂缓）。规划者是契约问题的**唯一终点**，但不是阻塞的**第一响应人**。
8. **审查范围 = 任务 diff + 定向抽查，不做全仓回扫**（v1.4 撤销原「approved 前全量回扫」义务）：逐行细读本任务 diff、核文件域与红线、跑**全量** test/typecheck、对被改动/新增的导出符号 grep 其**直接消费方**确认未破，即可下结论。全仓回归安全网 = 全量测试套件（每次合并前双闸照跑）+ 版本收口 V* 任务的整体验证 + 规划者**点名**的专项回扫（例外，须明示范围与理由）。审查中**偶然**发现域外问题仍按分流上报（域外致命→转规划者拆任务；拿不准→非阻断建议单转规划者），但不承担系统性搜寻义务、不得越域自改。

## 执行者工作流
1. 读本协议 + 你的任务 spec `tasks/<ID>.md` + [../AGENTS.md](../AGENTS.md)。
2. 在 [BOARD.md](BOARD.md) 确认该任务为 `ready` 且未被认领。
3. 建独立 worktree 切到任务分支（分支已由规划者创建；批内链式任务按批次说明自前一任务尖建）：
   ```
   ./coordination/agentctl.sh work <ID>
   cd ../斗地主.worktrees/<ID>
   npm --prefix test install   # 新 worktree 不含 node_modules，先装依赖
   ```
4. **只**在任务声明的文件域内实现：契约级种子转绿；覆盖级按 spec「必须覆盖用例清单」自写测试（可新增，不可改既有）。
5. 自检（交审前）：`npm --prefix test test`（**全量**套件）与 `npm --prefix test run typecheck` 全绿；UI/场景任务另做**视觉自审第一层**（四类硬伤勾销表，见「双层视觉预审关」）并留证据。
6. 落盘报告 `coordination/reports/<ID>.report.md`（用 [templates/report.md](templates/report.md)）。
7. 提交分支：`git add -A && git commit -m "feat(<ID>): ..."`。**批次作业**：一个窗口按序清完整批（各自提交 + 落报告），**批末只做一次交接**——用 [templates/handoff.md](templates/handoff.md) 输出中文交接 + 给**审查者**的可粘贴提示词（指针化：指向本批 `<ID>` 清单与各报告）。
8. 被置 `changes-requested`：按报告审查意见在原分支修复、重跑自检、更新报告，再次提审。
9. **卡壳上抛（快速失败）**：同一障碍自修 2 轮未过、缺能力/环境、或解决方案必然越域 → 报告置 `blocked`，写清复现命令、已尝试路径、失败证据、建议选项，**交接审查者兜底**；此后不提交规避性实现、不改测试、不继续空转。

## 审查者工作流
1. 读本协议 + 执行任务书 `tasks/<ID>.md` + 审查任务书（`tasks/R-*.md` 中本任务检查单）+ 执行者报告。
2. 评审 `git diff main..task/<ID>`：文件域与红线合规；**逐行细读新提交、读懂每处改动的正确性**；核对既有测试未被改动（`git diff main..task/<ID> -- test/` 只含规划者种子或执行者新增）；跑 `npm --prefix test test` + `run typecheck`；按检查单逐项核销，**鼓励超出检查单的自主判断**。
3. **定向抽查（替代全仓回扫）**：对本任务改动/新增的每个导出符号，grep 其直接消费方，确认调用点语义未破；spec 点名的交互面（如共享 helper 的既有消费者）逐一核。到此为止——**不做全仓系统性回扫**。
4. 结论与分流：
   - `changes-requested`（域内问题、执行者可修）：意见追加进 `reports/<ID>.report.md`，更新 BOARD 本任务行，打回执行者。
   - **兜底接管**：任务已被执行者置 `blocked`、或打回 ≥2 轮不收敛、或修复量明显小于一轮窗口往返成本 → 审查者在原分支、原文件域**直接修复**，报告单列「兜底修复披露」（范围/diff 摘要/自检证据），然后按本流程继续走向结论（兜底 diff 触及高风险面 → 升三闸）。
   - `blocked`（转规划者）：属 spec/测试矛盾、契约变更、文件域不足、环境不可达，兜底也无解 → 报告追加阻塞证据与裁定请求，BOARD 置 `blocked`，交接规划者（报告注明「待规划者裁定」）。
   - 域外发现（偶然）：**域外致命** → 转规划者拆定向修复任务（本次改动引入的回归须待规划者协调再定是否 `approved`；独立/存量问题不阻断本任务）；**拿不准** → 非阻断建议单转规划者。
   - `approved`：域内问题清零后，报告写评审证据（diff 审读范围 + 定向抽查结果 + 兜底披露如有），BOARD 置精确机器态 `approved`。**高风险任务**改置 `approved-pending-planner` 排队，等规划者批量把关认可后改回 `approved` 再合并。
5. 合并（常规任务 approved 后）：本人在 main 工作树重跑 test/typecheck 全绿，`./coordination/agentctl.sh claim <ID>` → `merge <ID>` → `release <ID>`。
6. **验收回复规划者 + 交接**：合并后在报告补「验收披露」段（评审结论、打回轮次、**兜底披露**、定向抽查结果、合并 commit、最终测试基线）。回合末用 [templates/handoff.md](templates/handoff.md) 输出中文交接 + 可粘贴提示词。
7. **ART 帽（图像任务）**：认领 ART-* 任务时按**执行者工作流**执行（生成/导入/取证/视觉自审第一层 + 报告），交接**规划者**审查；规划者 `approved` 后由本人执行合并三步。

## 规划者职责边界
- 产出：方案/拆解/spec/契约级种子/审查检查单/BOARD 真相源；**不写产品代码、不逐任务评审（ART-* 审查除外）、不合并**。
- 每轮验收披露后做终局裁定（BOARD 记 `裁定：确认 done` 或责令重开）。
- **接收审查者上交的四类入口**：① `blocked`（兜底无解的契约/spec/环境问题）→ 裁定：改 spec、补/改测试、拆新任务、调整文件域、补能力/环境前置，或暂缓；② **域外致命** → 拆定向修复任务派发；③ **拿不准** → 判断要不要修（要修另拆任务，不修记录归档）；④ **高风险合并把关** → 批量结构性把关后放行。均用既有 BOARD 建行/拆任务机制承接，不新增机器态。
- **ART-* 审查**：机械核（文件位置/meta/UUID/键断言/证据链）+ 视觉审（规划者能看图），结论写报告与 BOARD。
- **批量爆发式承担**（省耗 + 缓存友好）：打包兼容任务批次一次派发；批量把关高风险合并、批量仲裁上交项、批量视觉审②。集中爆发处理、爆发间闲置，避免逐任务冷调用。

## 协作运行模型（用户多窗口人工中转）
本节描述本协作在**现实中如何被驱动**：没有 agent 间自动消息，**用户在多个聊天窗口间人工粘贴**是唯一中转层。故一切设计以「**少窗口切换、短提示词、可自助读档**」为准。

- **批次循环（降低窗口切换频率）**：规划者把**兼容任务打成一个批次**一次派发；执行者**在一个窗口内按序清完整批**（逐任务提交与落报告，批内后续任务可自前一任务尖建分支链式推进），批末只做**一次**交接；审查者一次**批量审**整批、按依赖序合并；高风险合并**排队**进规划者批量把关。目标：把「每任务一次窗口往返」压成「每批次几次」。
  - **批次划分标准（唯一定义，处处引用）**：① 批内各任务**文件域互不冲突**（或显式声明链式顺序）；② **依赖有序**（被依赖者在前）；③ 规模以「一个执行窗口可连续完成」为度；④ 高风险任务可单独成批或显式标注，便于集中把关。
- **上下文种在仓库（提示词指针化）**：跨窗口不共享记忆，状态**全部种进仓库文件**——`tasks/<ID>.md`（任务书）、`reports/<ID>.report.md`（实现/评审/交接）、`BOARD.md`（状态真相源）、`coordination/seeds/`（预写种子搬运区）。**交接提示词只给「角色 + 批次/任务号 + 要读的文件路径」，不复述正文**。
- **每回合交接（硬要求）**：**任何角色**在一个窗口回合结束时，必须用**中文**向用户输出：① 本回合结论/状态；② **下一步该找哪个角色**；③ 一段**可直接粘贴到下一窗口的提示词**（指针化）；④ 待用户终审事项（如有）。用 [templates/handoff.md](templates/handoff.md)。

## 角色 × 模型能力校准（v1.4 当前配置）
核心协议保持模型无关；本节按当前配置（规划=**Claude**、审查/兜底/图像=**Codex**、执行=**Cursor**）做能力与 **token 经济**校准，换模型只改本节。总原则：实现与审查异家族、故障模式互补；**每一份贵模型 token 都花在便宜模型做不了的事上**。

- **能力取向与经济分工（各就其长）**：
  - **Claude（规划者·仲裁者）**——系统级推理、长上下文、对抗式契约/测试设计、**能看图**。单位 token 最贵 → **只做爆发式批处理**：前置一次爆发出整批 spec/契约/种子/检查单，后置一次爆发做批量把关 + 仲裁 + 视觉审②与终局裁定；**绝不逐任务冷调用、不逐行陪跑实现**（分散冷调用反复踩 prompt 缓存失效的冷读成本）。
  - **Codex（审查者·兜底者·图像执行者）**——精准代码审读、疑难调试与深推理、**多模态图像生成/处理**。深度花在刀刃上：① **diff 域审查**（逐行细读 + 定向抽查，**不再全仓回扫**——v1.4 撤销该义务正是为了把 Codex 的深度从「每任务重读全仓」的重复扫描里解放出来，用于↓）；② **兜底攻坚**——执行者卡壳的问题天然筛选出「真难题」，正对其长，且省去「打回↔重试」的多轮窗口往返；③ **ART-* 图像任务**——三 AI 中唯一具图像生成能力者。不烧在批量样板实现与系统性检索上——大面积回归交给测试套件。
  - **Cursor（执行者）**——单位 token 最便宜、IDE 原生、批量编码 / Cocos 编辑器实操 / 截图录屏取证吞吐最高。承担**全部常规实现**：接线、重构、覆盖级测试自写、多分辨率证据采集；**快速失败（≤2 轮）上抛兜底**，把贵模型的介入留给真难题，绝不在卡壳问题上空转烧 token；交审前跑全量自检，把明显问题挡在窗口往返之前。
- **互补与冗余**：实现（Cursor）与审查（Codex）异家族，各能抓到对方漏掉的问题；**高风险任务**加规划者（第三家族）批量结构性把关；UI 观感由规划者视觉审②独立覆盖（Codex 不判美观）。
- **高风险判定（唯一定义，处处引用）**：任务改动（含兜底 diff）触及以下任一即为**高风险**——① 共享契约文件（`assets/scripts/game/types.ts`、各 `index.ts` 桶，spec 授权的单行导出除外）；② `game` 状态机核心；③ `rules` 牌型比较/判定；④ 跨 ≥2 模块。高风险任务合并前须过规划者批量结构性把关（三闸）；其余为常规任务，审查毕连续合并。
- **任务类型校准（对齐 Cocos 流程）**：
  - **纯逻辑**（`rules`/`game`/`ai`/`flow`/`data`/ui 纯岛，客观 Vitest 门）：Cursor 实现 + 自写覆盖级测试 → Codex diff 审 + 定向抽查；契约级种子由规划者预写。
  - **UI/场景**（`P-*`，视觉 + 结构、测试弱）：Cursor 实现 + 实操取证 + 视觉自审① → 规划者视觉审② → 用户审美签收；Codex 审代码 diff + 证据链完整性（不判美观）。
  - **图像/美术**（`ART-*`，非文字 + 机械核 + 用户视觉终审）：Codex 生成/导入 + 自审① → 规划者机械核 + 视觉审② → 用户终审；合并由 Codex 执行（规划者 approved 在案）。
- **双层视觉预审关（UI/场景任务·用户裁决 2026-07-05·防「技术门全绿但视觉不过」）**：任何产出截图/实机画面的任务（`P-*`、scene 改动、V* 收口），交用户审美签收前必须连过两道——
  1. **实操方自审**（第一层·Cursor，ART 任务为 Codex）：逐张核**四类硬伤**——① 元素重叠（节点框相交）② 文字对比（浅底浅字/深底深字）③ 文字包裹（背景未包住文字、文字溢出）④ 闪烁/重渲（同帧重复触发动画、周期 render 抖动）。报告附「视觉自审勾销表」；有硬伤先自修，不达标不上交。
  2. **规划者视觉审**（第二层·Claude 能看图）：逐张复核各横屏×各相位截图，判美观达标线。不达标 → 打回（写明每张问题点，不上交用户）；达标 → 放行用户审美签收。结论写进 `R-*`/BOARD。
  3. **用户审美签收**（第三层·终审）：仅在双层达标后进行，用户只做主观审美取舍，不再兜 bug。
- **并发纪律**：多窗口并发以 **BOARD 为唯一序列化点**；worktree 隔离 + **主工作树常驻 main**（2026-07-04 事故纪律）不变；绝不假设他人的内存态。

## merge lane（机制不变，执行人为审查者）
- **双闸（常规任务）**：审查者写明 `approved` + 合并前重跑 test/typecheck 全绿。
- **三闸（高风险任务）**：`approved-pending-planner` + 规划者批量结构性把关认可 + 合并前双绿；规划者只加判断、不代合并（铁律 3）。ART-* 任务的 `approved` 判定人为规划者，合并三步仍由审查者执行。
- **单 lane**：`claim <ID>` 提交 `merge-claimed:<ID>`；已有他行 claim 则排队。
- **合并**：`merge <ID>` 用 `--no-ff`；message 记录 approved 证据。
- **释放**：`release <ID>` 置终态 `done <commit>`，清 worktree 与分支。`done <ID>` 为组合别名。

## 落盘约定
- 任务状态真相源：[BOARD.md](BOARD.md)（规划者维护结构；**BOARD 状态列禁用字面竖线 `|`**，会切坏 agentctl 的 awk 解析）。状态列必须使用可被脚本精确匹配的机器态：`todo`、`ready`、`in-progress`、`changes-requested`、`blocked`、`approved`、`approved-pending-planner`、`merge-claimed:<ID>`、`done <commit>`；阶段说明、证据摘要、自然语言进展不得混入状态列。`blocked` 的去向（待审查者兜底 / 待规划者裁定）写在**报告与交接**里，不进状态列。
- 执行者/审查者经 `agentctl.sh` 只改 BOARD **本任务状态行** + `reports/<ID>.report.md`（执行段/评审段/兜底披露段/验收披露段）。
- 代码：各自任务分支的提交；合并由审查者执行。
- **主工作树（仓库根目录）常驻 `main`**：任何角色（含规划者种子作业）的分支工作一律在独立 worktree 进行，绝不在主工作树 `git checkout` 任务分支（2026-07-04 事故教训）。
